# Варианты использования 

### Главная страница

**Разработчик:** Школьникова Т. В.

**Согласовано с:** Школьникова Т. В.

**Действующие лица:** Пользователь

**Описание**

Данный вариант использования описывает доступные пользователю действия
при открытии главной страницы.

**Предусловия**

1.  Пользователь заходит на сайт ИОС

**Основной поток событий**

1.  Система показывает страницу с приветствием (для Гостя пишется
    \"здравствуйте гость\", для авторизированного пользователя
    \"здравствуйте \*\*\*\", где \*\*\* - это логин, указанный при
    авторизации), которая закрывается при нажатии в любое место экрана

2.  Пользователь кликает в любое место на экране

3.  Система показывает пользователю интерфейс со следующими кнопками:

- Список институтов, под каждым институтом список направлений (элементы
  отсортированы по алфавиту)

- данные, указанные при регистрации (для авторизованных пользователей)

- Кнопка "Регистрация пользователей" (только для Администратора)

- Кнопка "Управление институтами" (только для Администратора)

- Кнопка "Просмотр учебного плана"

- Кнопка "Войти"

- Кнопка "Авторизации"

- Кнопка "Рассылка"

- Кнопка "Изменить или удалить данные о пользователях"(только для
  Администратора)

- Кнопка "Просмотр материалов дисциплины"(только для зарегистрированных
  пользователей)

- кнопка "Управление направлениями и кафедрами института"(только для
  Менеджера)

- кнопка "Мои курсы"(только для Преподавателя)

4.  Вариант использования завершается

### Управление учебным планом 

**Разработчик:** Школьникова Т. В.

**Согласовано с:** Школьникова Т. В.

**Действующие лица:** Менеджер

**Описание**

Данный вариант использования описывает создание, изменение и удаление
учебных планов для закрепленных за институтом Менеджера.

**Предусловия**

1.  Выполнен вариант использования "Просмотр учебного плана", института,
    за которым закреплен Менеджер

**Основной поток событий**

1.  Пользователь нажимает кнопку "Управление учебным планом".

2.  Система отображает интерфейс управления, а именно: кнопка
    \"Создать/Изменить учебный план\"

3.  Пользователь нажимает на кнопку \"Создать/Изменить учебный план\",
    выбирает направление, и загружает файл в формате Excel, структура
    которого соответствует учебному плану (столбцы: название дисциплины,
    количество часов, номер семестра, форма отчетности, преподаватель)

4.  Система обрабатывает данные из файла, при успешной обработке создает
    дисциплины в учебном плане на основе данных файла и выводит
    сообщение "загрузка прошла успешно". Если структура файла не
    подходит, то система выдает сообщение об ошибке и возвращает
    пользователя на шаг 3 основного потока.

5.  Вариант использования завершается

### Просмотр учебного плана

**Разработчик:** Школьникова Т. В.

**Согласовано с:** Школьникова Т. В.

**Действующие лица:** Пользователь

**Описание**

Данный вариант использования описывает доступные пользователю действия
при просмотре учебного плана

**Предусловия**

1.  Выполнен вариант использования «Главная страница»

**Основной поток событий**

1.  Пользователь нажимает кнопку "Просмотр учебного плана".

2.  Система отображает список институтов. При нажатии на название
    института отображается список его направлений (название
    направление - ссылка, ведущая на учебный план направления).

3.  Пользователь нажимает на название направления.

4.  Система отображает учебный план выбранного направления в виде
    таблицы. Таблица содержит следующие столбцы: «Название дисциплины»
    (при нажатии н аназвание дисциплины выполняется ВИ "Просмотр
    материалов дисциплины"), «Количество часов», «Номер семестра»,
    «Форма отчетности», «Преподаватель». Учебный план отображается
    только для просмотра, без возможности сортировки, фильтрации или
    редактирования. Если Пользователь является Менеджером, то система
    отображает кнопку "Управление учебным планом".

5.  Вариант использования завершается.

### Авторизация

**Разработано:**Школьникова Т. В.

**Согласовано с:** Школьникова Т. В.

**Действующие лица:** Гость

**Описание**

Данный вариант использования описывает процесс авторизации пользователя
в системе.

**Предусловия**

1.  Выполнен вариант использования «Главная страница»

**Основной поток**

1.  Пользователь нажимает на кнопку "Войти"

2.  Система выводит форму с заголовком "Авторизация в
    информационно-образовательную системе вуза" и полями для ввода:
    «Логин», «Пароль» и кнопки «Запомнить меня», «Забыли пароль?» и «Ок»
    (становится активной после ввода данных).

3.  Пользователь вводит данные и нажимает кнопку «Ок» . Если
    пользователь нажимает кнопку "Запомнить меня", то система сохраняет
    логин при последующем входе. Если пользователь нажимает кнопку забыл
    пароль, то система выводит сообщение о том, что пользователь может
    обратиться к администратору.

4.  Система проверяет введенные данные (логин должен состоять из
    латинских букв, пароль не должен быть пустым) и определяет, является
    ли этот вход первым для пользователя. Если это первый вход, система
    предлагает сменить пароль на собственный. Если логин и пароль
    введены верно, то система входит в аккаунт пользователя и отображает
    главную страницу. Если введенные данные не верные, то поля с
    неверными данными подсвечиваются. Если неудачных попыток больше 3,
    то выполняется переход к пункту 1 альтернативного потока .

5.  Вариант использования завершается.

Альтернативный поток 1:

1.  Система показывает всплывающее окно с предупреждением о превышении
    лимита попыток, содержащее кнопку "Понятно"

2.  Пользователь нажимает на кнопку "Понятно"

3.  Всплывающее окно исчезает

4.  Система блокирует форму на 20 минут, отключая все элементы формы.
    Через 20 минут система разблокирует форму авторизации и выполняет
    переход к 1 пункту основного потока.

### Отправка сообщений в форуме 

**Разработчик:** Школьникова Т. В.

**Согласовано с:** Школьникова Т. В.

**Действующие лица:** Преподаватель и Студент

**Описание**

Данный вариант использования описывает процесс написания и отправки
сообщения в форуме, привязанном к конкретной дисциплине.

**Предусловия**

1.  Выполнен вариант использования "Просмотр материалов дисциплины"

**Основной поток событий**

1.  Пользователь в интерфейсе форума нажимает кнопку «Написать
    сообщение».

2.  Система отображает текстовое поле для ввода сообщения.

3.  Пользователь вводит текст сообщения (количество символов не
    ограничено).

4.  Система отображает кнопки "отправить" и "отмена", если пользователь
    нажимает на кнопку "отмена", то выполняется АП1.

5.  Пользователь нажимает кнопку "отправить".

6.  Система проверяет, что поле сообщения не пустое, если поле пустое,
    то система выводит сообщение "нельзя отправить пустое сообщение".

7.  Система сохраняет сообщение общей ленте сообщений форума и снизу
    сообщения отображает логин отправителя.

8.  Вариант использования завершается.

**Альтернативный поток 1:**

1.  На шагах 2 или 3 основного потока пользователь нажимает кнопку
    «Отмена».

2.  Система закрывает текстовый редактор, не сохраняя введенный текст, и
    возвращает пользователя к ленте сообщений форума.

3.  Вариант использования завершается.

### Управление институтами

**Разработчик:** Школьникова Т. В.

**Согласовано с:** Школьникова Т. В.

**Действующие лица:** Администратор

**Описание:**

Данный вариант описывает процесс создания нового института в системе.

**Предусловия**

1.  Выполнен вариант использования "Главная страница"

**Основной поток событий**

1.  Пользователь нажимает кнопку "Управление институтами".

2.  Система отображает страницу со списком всех институтов,
    зарегистрированных в системе и кнопкой "Создать новый институт" .
    Для каждого института в списке отображается: название института, ФИО
    менеджера закрепленного за институтом, email менеджера (указанный
    при регистрации).

3.  Пользователь нажимает кнопку "Создать новый институт".

4.  Система открывает форму регистрации, в которой кнопка "Создать" и
    следующие поля: логин менеджера (при нажатии на поле отображается
    список для выбора с логинами зарегистрированных как Менеджер
    пользователей), наименование института (обязательное текстовое
    поле).

5.  Пользователь заполняет поля и нажимает кнопку "Создать".

6.  Система проверяет данные. Если данные корректны, то система создает
    институт, за которым закреплен менеджер и выводит сообщение
    "Сохранение прошло успешно". Если данные некорректны, то система
    выводит сообщение "Проверьте корректность вводимых данных".

**Описание:** Данный вариант использования описывает процесс очистки

1.  Наступила календарная дата 30 августа.

1.  30 августа система запускает процесс очистки форумов.

### Отправка сообщений в рассылке

**Разработчик:** Школьникова Т. В.

**Согласовано с:** Школьникова Т. В.

**Действующие лица:** Зарегистрированный пользователь

**Описание**

Данный вариант использования описывает процесс отправки сообщений с
помощью рассылки разными группами пользователей.

**Предусловия**

1.  Выполнен вариант использования "Главная страница"

**Основной поток:**

1.  Пользователь нажимает на кнопку "Рассылка"

2.  Система отображает форму со следующими полями: "Кому", "Введите
    сообщение" и кнопка "Отправить".

3.  Пользователь нажимает на поле "Кому" и вводит логин получателя.

4.  Система проверяет доступность логина. Если пользователь имеет роль
    Студент, то ему доступен логин Преподавателя, закрепленного за
    данной дисциплиной. (Преподавателю - Студента, Администратору -
    любого пользователя, Менеджеру - Преподавателя). Если логин
    получателя недоступен отправителю, то система выводит сообщение
    "Получатель недоступен". Если доступен, то поле для ввода сообщения
    становится доступным. Может быть указано несколько логинов.

5.  Пользователь нажимает на поле "Введите сообщение", вводит сообщение
    и нажимает кнопку "Отправить".

6.  Система отправляет сообщение на почту, привязанную к выбранному
    логину. Если указано несколько логинов, то система отправляет
    сообщение на каждую почту, привязанную к данным логинам.

7.  Вариант использования завершается.

### Регистрация пользователей

**Разработано:** Школьникова Т. В.

**Согласовано с:** Школьникова Т.В.

**Действующие лица:** Администратор

**Описание**

Данный вариант использования описывает процесс регистрации
пользователей.

**Предусловие**

1\. Выполнен вариант использования "Главная страница"

**Основной поток событий**

> 1\. Пользователь нажимает кнопку \"Регистрация\".
>
> 2\. Система отображает форму выбора типа регистрации с вариантами:
> \"Один пользователь\" или \"Группа студентов\".
>
> 3\. Пользователь выбирает \"Один пользователь\". Если он выбирает
> \"Группа студентов\", то выполняется АП1.
>
> 4\. Система открывает форму регистрации с полями:
>
> Фамилия (обязательное текстовое поле)
>
> Имя (обязательное текстовое поле)
>
> Отчество (необязательное текстовое поле)
>
> Email (обязательное, текстовое поле с форматом ввода email)
>
> Роль (обязательное поле с выбором из списка: Студент, Преподаватель,
> Менеджер, Администратор)
>
> Если роль \"Студент\" - появляется поле \"Направление обучения\"
> (обязательное текстовое поле), "Курс" (обязательное поле с выбором
> 1-4), "Номер зачетки" (обязательное поле - 8 уникальных цифр). Если
> роль "Преподаватель" - появляются поля "Кафедра" (обязательное
> текстовое поле), "Должность" (обязательное поле с выбором: ассистент,
> доцент, профессор, заведующий кафедрой). Если роль "Менеджер" -
> появляется поле "Наименование института" (обязательное текстовое поле)
>
> 5\. Пользователь заполняет обязательные поля.
>
> 6\. Система отображает кнопку \"Зарегистрировать\".
>
> 7\. Пользователь нажимает на кнопку "Зарегистрировать"
>
> 8\. Система проверяет данные на корректность, если при проверке данных
> найдены ошибки: система показывает сообщение об ошибке с указанием
> проблемных полей, форма отображается с ранее введенными данными,
> ошибки подсвечиваются.
>
> 9\. При успешной проверке система:
>
> Создает учетную запись (В качестве логина будет фамилия и инициалы
> пользователя, которые будут генерироваться автоматически латинскими
> буквами. Если генерируется логин, который уже есть в системе, тогда
> [Пользователю]{.mark} будет предложено ввести логин вручную, чтобы он
> стал уникальным)
>
> Генерирует временный пароль
>
> Отправляет пароль и логин на указанный email
>
> 10\. Система отображает сообщение об успешной регистрации.
>
> 11\. Вариант использования завершен.

**Альтернативные потоки событий**

АП1 Регистрация группы студентов

> 1\. Пользователь нажимает на кнопку \"Группа студентов\":
>
> 2.Система отображает форму загрузки файла со списком студентов (.csv
> или .xlsx)
>
> 3\. Пользователь загружает файл и нажимает \"Импорт\"
>
> 3.Система проверяет формат файла и данные (таблица должна содержать
> три столбца: в первых двух общая информация, в третьем номер зачетки.
> В названии файла написано направление. На каждый курс и направление
> отдельный файл со списком данных студентов.)
>
> 4\. Для каждого конкретного студента из файла система:
>
> Создает учетную запись
>
> Генерирует временный пароль
>
> Отправляет пароль на email
>
> 5\. Система выводит сообщение об успешной загрузке.
>
> 6\. Вариант использования завершен.

### Изменение материалов дисциплины

**Разработчик:** Школьникова Т. В.

**Согласовано с:** Школьникова Т. В.

**Действующие лица:** Преподаватель

**Описание**

Данный вариант использования описывает процесс загрузки и удаления
материалов дисциплины, а также их структуры

**Предусловия**

1.  Выполнен вариант использования "Просмотр материалов дисциплины"

**Основной поток событий:**
